# デプロイ手順（公開デモ）

## 位置づけ

本番の抽出作業は**ローカルで行う**。デプロイするのは、第三者が手順を再現できる
**公開デモ**（`PUBLIC_MODE=1`）だけ。デモは訪問者が自分で PDF をアップロードして試す形で、
サーバーに恒久的なデータを持たない。

## 公開デモの安全設計

この画面には認証が無い。そのため公開側では次の制約をかけている。

- データ置き場を**プロセスごとの一時ディレクトリ**に差し替える（再起動で消える）
- アップロードにサイズ上限（40 MB）を設ける
- ローカルのデータへ辿れる経路を持たない（`WORKBENCH_DATA` を参照しない）

## Render へのデプロイ

構成は `render.yaml`（Blueprint）に定義済み。

1. Render で「New → Blueprint」からこのリポジトリを選択
2. `render.yaml` が読み込まれ、`PUBLIC_MODE=1` の Web サービスが作成される
3. 以後は **main ブランチへの push で自動デプロイ**される

サーバーは gunicorn（ワーカー 1）で起動する。ジョブの進捗状態をプロセス内に持つため、
**ワーカーを増やす場合は状態管理の外部化が必要**（現状はスケールしない前提の設計）。

## ロールバック

- Render のダッシュボード → 対象サービス → **Rollback** で直前のデプロイに戻せる
- あるいは main ブランチを `git revert` して push すれば、自動デプロイで前の挙動に戻る
  （デモはステートレスなので、データ移行の考慮は不要）

## 無料プランでの注意

- 15 分アクセスが無いとスリープし、次のアクセスで復帰に約 1 分かかる
- ファイルシステムは ephemeral（再デプロイ・再起動で消える）— デモの設計はこれを前提にしている
