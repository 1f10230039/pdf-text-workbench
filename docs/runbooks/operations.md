# 運用手順

## 日常の使い方（推奨フロー）

前処理の調整・確認作業は無い（破壊的な前処理は柱の除去だけ・全文書共通。
→ [ADR-0009](../adr/0009-no-margin-cut.md)）。文書を置いたらそのまま確認へ進める。

1. **ヒットを確認**（確認モード） — 検索語を含む箇所を 1 件ずつキューで確認する。
   修正（足す・繋ぐ・分ける・除外）はカード上で完結し、すべて設定 JSON に記録される。
   ヘッダー・フッター・目次などに由来するヒットは、理由コードを選んで単位ごと外す。
   ✓ は取り消して未確認に戻せる（記録ごと消える）。
   ホームの進捗バーが「次にやること」を出し分ける
2. **全冊書き出し** — CSV（全件＝監査記録）と Excel（採用のみ）を出力する
3. **出現率** — 文書ごとの総文数・ヒット文数・ページ数と率を一覧・CSV 出力する
   （分子・分母とも機械判定＝手動修正の影響を受けない）

## キャッシュ

| したいこと | 方法 |
|---|---|
| 未解析の文書を一括で解析しておく | UI のジョブ（自動で走る）または `python warm_cache.py 文書名...` |
| キャッシュを作り直す | `WORKBENCH_DATA/.cache/` を削除して再解析（結果は変わらない） |

キャッシュは「PDF の更新時刻 ＋ 結果に影響する設定の署名」で管理される。
設定を変えると該当文書だけが自動で再解析になる。

## バックアップと履歴

- 設定 JSON は保存のたびに直前の版が `設定/履歴/` に自動退避される
- 書き出しは既存ファイルを黙って上書きしない（上書き／別名／中止を選択）

## トラブルシューティング

| 症状 | 原因と対処 |
|---|---|
| xlsx の書き出しに失敗する | 出力先のファイルを Excel / KH Coder で開いたまま。閉じてから再実行 |
| 「◯件のルールが当たっていません」と警告が出る | パラメータ変更でブロックの切れ方が変わり、保存済みの修正ルールが外れた。警告の一覧から付け直すか削除する |
| 初回の解析が遅い | 正常（数百ページの文書で数十秒）。2 回目以降はキャッシュで数秒になる |
| 表の中身が 1 行に潰れて抽出される | 図解の枠線を表と誤検出している。該当ページで「表の検出をやめる」を実行 |
| ページ番号・章名がヒットに混ざる | 反復しない位置のものは残る仕様。確認モードで「ヘッダー／フッターのため除外」を選ぶ |
