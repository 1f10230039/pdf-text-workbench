# 運用手順

## 日常の使い方（推奨フロー）

1. **切り取りと除外** — 文書ごとに 3 つの判断を記録して消化していく画面。
   未チェック / チェック済みの 2 タブと進捗表示つきで、並び順は「検索語を巻き込んでいる文書 →
   巻き込みが多い文書 → 名前順」（急ぐものが先頭に来る）。文書を開くと全ページの原本が並び、
   - **境界（ヘッダー・フッター）** — どのページでも上下の境界線をドラッグして調整。
     切られる本文（赤）／残る本文（緑）／戻ってくるページ番号（橙）が即時に色分けされ、
     機械診断の提案値も 1 クリックで使える。記録は上下まとめて 1 回
   - **除外ページ（表紙・目次）** — 除外中のページは暗い覆いつきで表示され、クリックで解除。
     機械の候補（表紙・目次らしいページ）はバッジで提示される
   
   余白や除外を変えたら「解析を作り直す」で該当文書のキャッシュを再生成する
   （押し忘れても次の解析時に自動で作り直される）
2. **ヒットを確認**（確認モード） — 検索語を含む箇所を 1 件ずつキューで確認する。
   修正（足す・繋ぐ・分ける・除外）はカード上で完結し、すべて設定 JSON に記録される
3. **全冊書き出し** — CSV（全件＝監査記録）と Excel（採用のみ）を出力する

## キャッシュ

| したいこと | 方法 |
|---|---|
| 未解析の文書を一括で解析しておく | UI のジョブ（自動で走る）または `python warm_cache.py 文書名...` |
| キャッシュを作り直す | `WORKBENCH_DATA/.cache/` を削除して再解析（結果は変わらない） |

キャッシュは「PDF の更新時刻 ＋ 結果に影響する設定の署名」で管理される。
設定を変えると該当文書だけが自動で再解析になる。

## バックアップと履歴

- 設定 JSON は保存のたびに直前の版が `設定/履歴/` に自動退避される
- 書き出しは既存ファイルを黙って上書きしない（上書き／別名／中止を選択）

## トラブルシューティング

| 症状 | 原因と対処 |
|---|---|
| xlsx の書き出しに失敗する | 出力先のファイルを Excel / KH Coder で開いたまま。閉じてから再実行 |
| 「◯件のルールが当たっていません」と警告が出る | パラメータ変更でブロックの切れ方が変わり、保存済みの修正ルールが外れた。警告の一覧から付け直すか削除する |
| 初回の解析が遅い | 正常（数百ページの文書で数十秒）。2 回目以降はキャッシュで数秒になる |
| 表の中身が 1 行に潰れて抽出される | 図解の枠線を表と誤検出している。該当ページで「表の検出をやめる」を実行 |
| 文が途中で切れている | ヘッダー・フッターの境界が本文を巻き込んでいる可能性。「切り取りと除外」で原本を見ながら境界を調整 |
