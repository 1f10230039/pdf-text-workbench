# 0005. 罫線表は「行」単位のブロックに再構成する

- Status: Accepted（[0010](0010-table-cell-group-splits.md) が一部を補正：行内に複数のセル群が連結される場合は手動で分割できる）

## Context

報告書には KPI 表などの罫線表が多い。PDF のテキストをそのまま拾うと、
表のセルは描画順（列ごと・座標順）でバラバラに出てきて、
「指標名と数値が別々の断片になる」「1 つの列だけが連結される」など、意味の取れないテキストになる。

## Decision Drivers

- 表の中のキーワードも分析対象にできること（表にしか言及が無い文書がある）
- セル断片単体では意味が取れない（「60%」だけ拾っても何の値か分からない）
- 表全体を 1 かたまりにすると大きすぎ、無関係な行まで巻き込む

## Considered Options

1. **表を検出し、「1 行 = 1 ブロック」に再構成する** — 行は「どの指標がどの値か」が揃う最小単位
2. 表領域をまるごと除外する — 表にしか記述が無い文書で取りこぼしが出る
3. セル単位で扱う — 断片化して意味が取れない
4. 表全体を 1 ブロックにする — 1 単位が数百〜千文字級になり、分析単位として粗すぎる

## Decision

罫線（線分）から表を検出し、セルの y 座標から行バンドを推定して
**表の 1 行を 1 ブロック**に組み直す。結合セル（複数行にまたがるセル）は先頭行に属するとみなす。
罫線が無い表は人が範囲を指定でき、逆に「罫線はあるが表ではない」レイアウト枠は
ページ単位で検出を止められる（どちらも設定 JSON に記録される）。

## Consequences

- (+) 表の中の言及を「指標＋値」の揃った行として抽出できる
- (+) 誤検出（図解の枠線など）への対処が記録つきの操作として用意されている
- (−) 行の復元はセル座標のヒューリスティックであり、複雑な入れ子の表では割れることがある
- (−) 行テキストはセルの連結なので、文としての句読点構造は持たない
