# 0003. LLM による自動抽出を採用しない

- Status: Accepted

## Context

「PDF から本文を取り出して整形する」タスクは、LLM（生成 AI）に任せる選択肢もある。
実際、レイアウト解析や表の読み取りでは LLM ベースの手法が高い精度を出すことがある。

## Decision Drivers

- 同じ入力から常に同じ出力が得られること（このツールの中核要件。[ADR-0002](0002-settings-json.md)）
- 出力の正誤を人が検証・説明できること
- 数十冊 × 数百ページを繰り返し処理するコストと速度

## Considered Options

1. **ルールベースの機械判定 ＋ 人の修正（記録つき）** — 決定的で説明可能。ただし手作業が残る
2. LLM に本文抽出・整形を任せる — 高精度が期待できるが、temperature=0 でも出力は完全には
   決定的でなく、同じ PDF から毎回同じテキストになる保証がない。誤りの箇所を特定して
   説明することも難しい
3. ハイブリッド（LLM の出力を人が全件レビュー） — レビューコストが 1 の手作業と変わらず、
   非決定性の問題は残る

## Decision

オプション 1 を採用する。機械判定は座標・フォント・罫線などの**レイアウト由来の規則だけ**で行い、
規則で判定できない箇所は人が指定して記録する。LLM は抽出パイプラインのどこにも置かない。

## Consequences

- (+) 出力が決定的になり、「設定 JSON を渡せば同じ結果」が成立する
- (+) すべての判定に根拠（座標・サイズ・罫線・記録されたルール）があり、説明できる
- (+) API コスト・レート制限・モデル更新による挙動変化と無縁
- (−) レイアウト規則で拾えないケースの手作業は残る（UI 側で修正コストを下げて補う）
