# 0010. 表の行に複数のセル群が連結される場合はセル群の境目で分割する

- Status: Accepted
- Amends: [0005](0005-table-row-blocks.md)（行単位の再構成そのものは維持する）

## Context

KPI 表には、1 つの行の中に「目標」と「実績」のように**列見出しを異にする箇条書きのセル群**が
並ぶレイアウトがある。0005 の「1 行 = 1 ブロック」で再構成すると、この型では
将来の目標と過去の実績が 1 単位に連結され、単位の意味的な一貫が壊れる
（検索語の共起に、同じ行の別セル群の語が混ざる）。
また結合セルの帰属はヒューリスティックであり、この型では行の鍵となるセルが
別の行に付くことがあるため、「行全体」も忠実には復元できていない。

## Decision Drivers

- 単位は「機械が信頼できる境界で切れる最小」であるべき（本文は句点、表内は構造）
- 表のセル内の文字（句点・中黒）は境界として信頼できない（中黒は固有名詞にも使われる）
- 同じ表の年違い（デザイン変更でラベル再掲の有無が変わる）で手続きが割れてはいけない

## Considered Options

1. **行のまま**（0005 のとおり）— 意味の異なるセル群が 1 単位に混ざる
2. セル単位に分ける — 0005 で却下済み（断片化）
3. 中黒「・」を区切りにする — 固有名詞（「ボストンジーン・ジャパン」型）が粉砕される
4. **セル群の境目で、人が名指しして分ける** — 境目は列バンド由来＝構造的で、指定は設定 JSON に残る

## Decision

`splits`（0002 の手動分割）を**表の行ブロックにも適用**する。ルールの形は通常ブロックと
同じ `{"page", "text", "line", "reason"}` で、`text` は行の raw（列の組み直し後の生text）、
分けた後の raw も同じ列の組み直しで作り直す。理由コードは「セル群の癒着」。

- 対象は「列見出しを異にする箇条書きセル群が 1 行に連結されている」場合のみ。
  **単一セルの中の箇条書きは行全体のまま**（0005 の既定を変えない）
- 分割エンジンは、分けた**両方の断片**にルールが当たらなくなるまで照合を続ける
  （操作の順序に依存しない。UI で作れるルールはエンジンが必ず適用できること）

## Consequences

- (+) 目標と実績が別単位になり、検索語の共起が「同じセル群に書かれた語」に限定される
- (+) 指定・理由が設定 JSON に残り、同一入力から同一出力が再現される
- (−) 境目の指定は人手（自動検出はしない。0003 の方針どおり規則外の判断は人が名指しする）
- (−) 結合済みの表の行は分割の対象外（先に結合を戻す）
