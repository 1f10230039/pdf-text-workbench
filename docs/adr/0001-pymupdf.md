# 0001. PDF 抽出ライブラリに PyMuPDF を採用する

- Status: Accepted

## Context

企業の報告書 PDF は多段組・図表・装飾が多く、単純なテキスト抽出では読み順や文の境界が壊れる。
座標・フォントサイズ・太字などのレイアウト情報を行単位で取得できるライブラリが必要。

## Decision Drivers

- 行・スパン単位の座標とフォント情報（サイズ・太字フラグ）が取れること
- 罫線（線分）を取得して表検出に使えること
- ページ画像のレンダリングも同じライブラリでできること（UI で原本を表示するため）
- 処理速度（数百ページ × 数十冊を繰り返し解析する）

## Considered Options

1. **PyMuPDF (fitz)** — C 実装で高速。`get_text("dict")` で行・スパンの座標とフォント情報、
   `find_tables()` で罫線表、`get_pixmap()` でレンダリングまで一通り揃う
2. **pdfplumber** — 表抽出に強いが、pdfminer ベースで大量ページの繰り返し解析には遅い
3. **pdfminer.six** — 低レベル情報は取れるが、表・レンダリングは別途必要

## Decision

PyMuPDF を採用する。抽出・表検出・レンダリングを 1 ライブラリに寄せることで、
座標系の変換やライブラリ間の食い違いを持ち込まない。

## Consequences

- (+) 行の座標・サイズ・太字・罫線・ページ画像がすべて同じ座標系で扱える
- (+) 数百ページの文書でも実用速度で繰り返し解析できる
- (−) AGPL ライセンスのため、組み込み配布には注意が要る（本ツールはローカル利用が前提）
- (−) スレッドセーフではない → [ADR-0007](0007-pymupdf-lock.md) で対処
